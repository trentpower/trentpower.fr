trentpower.fr — Open Graph + image-system specification
========================================================

This file is repo-local design documentation. It is NOT deployed to
the live host; it lives under design/ alongside other internal
documentation. The brief asks for a specification of the rules so
future edits stay consistent.


1. Image directory structure
----------------------------

    public/
      favicon.ico                ← root-level browser-compat copies;
      favicon.svg                  byte-equal to /images/icons/<same>
      apple-touch-icon.png
      icon-192.png
      icon-512.png

      images/
        og/                      ← Open Graph PNG masters + WebP/AVIF
        icons/                   ← canonical favicon + app icons
        portraits/               ← trent-power.{jpg,webp,avif} et al.
        qr/                      ← QR + print-qr SVGs
        architecture/            ← architecture diagrams in 5 langs

      images-manifest.json       ← machine-readable manifest

      source/
        images/                  ← per-image text mirrors
          og/<name>.png.base64.txt
          og/<name>.webp.base64.txt
          og/<name>.avif.base64.txt
          qr/<name>.svg.txt
          architecture/<name>.svg.txt
          portraits/<name>.{jpg,webp,avif}.base64.txt
          icons/<name>.{ico,svg,png}.base64.txt or .txt
        favicon.{ico,svg,png}.base64.txt or .txt
        apple-touch-icon.png.base64.txt
        icon-{192,512}.png.base64.txt


2. Canonical formats
--------------------

  • PNG is the canonical Open Graph and Twitter metadata image.
  • JPG is the canonical portrait master.
  • SVG is the canonical QR and architecture-diagram master (vector,
    no derivatives needed).
  • WebP is a static optimisation derivative — derived from PNG/JPG
    via cwebp before release.
  • AVIF is a static advanced optimisation derivative — derived from
    PNG/JPG via avifenc before release.

  Derivatives are uploaded as ordinary static files. The server does
  NOT generate, transform, negotiate, or optimise images dynamically.

  Required wording (also recorded in /images-manifest.json):

      WebP and AVIF files are static derivatives generated locally
      from canonical PNG or JPG files before release. They are
      uploaded as normal static files. The server does not generate,
      transform, negotiate, or optimise images dynamically.

      PNG remains the canonical Open Graph and Twitter metadata
      image. WebP is used as a practical modern optimisation
      derivative. AVIF is used as an advanced optimisation
      derivative where quality and complexity remain acceptable.


3. PNG as primary OG format
---------------------------

  All og:image and twitter:image metadata MUST reference PNG only.

  Correct:
    <meta property="og:image" content="https://trentpower.fr/images/og/source-og.png">
    <meta name="twitter:image" content="https://trentpower.fr/images/og/source-og.png">

  Wrong:
    <meta property="og:image" content="https://trentpower.fr/images/social/source-og.png">  # legacy path
    <meta property="og:image" content="https://trentpower.fr/images/og/source-og.webp">     # wrong format
    <meta property="og:image" content="https://trentpower.fr/images/og/source-og.avif">     # wrong format

  validate_images.py enforces this.


4. WebP as static optimisation derivative
-----------------------------------------

  Encoder: cwebp -q 90 -m 6 -metadata none
  Generated by: tools/generate_image_derivatives.py
  Pinned mtime: derivative mtime is forced equal to its master's
                mtime so subsequent rebuilds are stable.

  Use only inside in-page <picture> elements when displaying images
  inline (e.g. cover photos, body imagery). NEVER inside og:image
  metadata.

  Example:
    <picture>
      <source srcset="/images/og/source-og.avif" type="image/avif">
      <source srcset="/images/og/source-og.webp" type="image/webp">
      <img src="/images/og/source-og.png"
           alt="Source page preview for trentpower.fr"
           width="1200" height="630"
           loading="lazy" decoding="async">
    </picture>


5. AVIF as advanced optimisation derivative
-------------------------------------------

  Encoder: avifenc --min 20 --max 30 --speed 4 -y 444
  Generated by: tools/generate_image_derivatives.py

  If serif typography shows artefacts, the encoder presets can be
  tightened to:

    avifenc --min 16 --max 24 --speed 4 -y 444

  Same in-page-only rule as WebP. AVIF may be larger than WebP at
  these settings; size monitoring belongs in validate_images.py.


6. No dynamic image generation
------------------------------

  • No PHP image conversion.
  • No ImageMagick on server.
  • No CDN transformations.
  • No JavaScript image conversion.
  • No runtime negotiation beyond browser <picture> support.

  All derivatives are produced locally before release. The server
  serves the bytes already in public/.


7. Root favicon compatibility rule
----------------------------------

  Browsers and installers expect the following five files at the
  document root:

    /favicon.ico
    /favicon.svg
    /apple-touch-icon.png
    /icon-192.png
    /icon-512.png

  The canonical copies live under public/images/icons/. The
  root-level copies are byte-equal duplicates kept solely for
  platform compatibility.

  validate_images.py refuses to ship if /<file> ≠ /images/icons/<file>
  byte-for-byte.


8. Source mirror rule
---------------------

  Every public image has a plain-text source mirror at /source/.

  SVG (text):
    /images/qr/qr-home.svg
      → /source/images/qr/qr-home.svg.txt   (verbatim text mirror)

  Raster (PNG/JPG/WebP/AVIF/ICO, binary):
    /images/og/source-og.png
      → /source/images/og/source-og.png.base64.txt
        with header:
          # Base64 mirror of:
          /images/og/source-og.png
          # SHA-256: <sha256-b64>
          # MIME:    image/png
          # Size:    <bytes> bytes
          <wrapped base64 body, 76 chars/line>

  Mirrors are produced by tools/generate_source_view.py (binary
  helper functions added in commit G). They are tracked in
  public/source/source-manifest.json under the top-level "images"
  array — separate from the editorial "files" array so the
  rendered /source/ catalogue stays composed and editorial.

  validate_source_mirrors.py enforces:
    • every image-mirror record's live file exists,
    • every mirror file exists,
    • the manifest sha256 matches the live disk bytes.


9. Metadata rules
-----------------

  /images-manifest.json is the machine-readable image surface. Each
  entry records:

    path, role, canonical, derivative_of, mime, width, height,
    size_bytes, sha256, source_mirror, generated_by

  Roles (closed set):
    open_graph              — canonical PNG OG
    open_graph_derivative   — WebP/AVIF derived from a canonical PNG
    icon                    — favicon / app-icon copies
    portrait                — canonical JPG portrait
    portrait_derivative     — WebP/AVIF derived from a canonical JPG
    qr                      — QR SVG
    architecture_diagram    — architecture SVG

  Generation timestamp uses today's UTC date so two builds within a
  day produce identical bytes.


10. Validation rules
--------------------

  Build fails if:
    • OG metadata references /images/social/ (legacy)
    • OG metadata references .webp or .avif
    • any /images/og/*.png is not 1200×630
    • any /images/og/*.png has alpha
    • any AVIF/WebP derivative exists without its master PNG/JPG
    • root icon copies differ from /images/icons/ canonical versions
    • source mirrors are missing
    • images-manifest entries are missing
    • image-mirror sha256 disagrees with live disk
    • banned authorship phrasing appears in public output

  Build warns if:
    • PNG OG file exceeds 300 KB
    • canonical OG PNG is not referenced by any og:image in active HTML

  Build fails (hard) if:
    • PNG OG file exceeds 500 KB

  Validators:
    tools/validate_images.py                — image-system gate
    tools/validate_source_mirrors.py        — text + image mirrors
    tools/validate_language_consistency.py  — authorship phrasing
    tools/predeploy_check.py                — meta-gate (13 steps)


Appendix — operational notes
-----------------------------

  • Originals live at assets-source/og-originals/ (gitignored, local
    canonical reference). The deployed authoritative copies live at
    public/images/og/.
  • Re-import: drop a fresh PNG set into assets-source/og-originals/
    and run python3 tools/import_og_pngs.py. The importer normalises
    filenames (BE → AE spelling), resizes wrong-dimension PNGs by
    Lanczos when aspect drift is under 0.5%, and strips alpha.
  • Re-derive: subsequent tools/build.sh runs invoke
    generate_image_derivatives.py automatically; it skips up-to-date
    derivatives via mtime comparison.
