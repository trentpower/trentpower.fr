# Reproducibility

How to rebuild a published edition from source and get the same bytes, what is
guaranteed to be deterministic, and the few things that are deliberately not.

## The claim

```sh
git checkout edition/<YYYY-MM-DD>
python3 tools/build/fetch_licensed_fonts.py   # restore licensed fonts (verified)
bash tools/build/build.sh --check             # re-render + seal + verify
```

Re-rendering the site from `content/` sources reproduces the committed `public/`
tree. The `--check` build runs the drift gate and **fails closed** if any committed
generated byte does not rebuild from its source — so a clean checkout either
reproduces the edition exactly or the build stops.

This is exercised continuously: the `build-check` job
([publication-check.yml](../.github/workflows/publication-check.yml)) re-renders on a
clean GitHub-hosted runner for every promotion PR, and the release workflow
([release.yml](../.github/workflows/release.yml)) re-renders again before it builds
and attests the release archive (SLSA Build L3 — see [provenance.md](provenance.md)).

## What is deterministic

The release archives are byte-deterministic by construction
([tools/release/build_release_archives.py](../tools/release/build_release_archives.py)):

- file order is sorted (locale-independent byte order);
- mtimes are pinned to `<edition>T00:00:00Z` for every entry;
- tar `uid`/`gid`/`uname`/`gname` are normalised to `0`/empty (no host metadata);
- gzip is written with `mtime=0` and no filename header;
- zip `date_time` and `external_attr` are pinned.

Building twice from the same source tree produces identical `.zip` and `.tar.gz`
bytes; the SHA-256 values in `SHA256SUMS` pin the sequence. The CycloneDX SBOM is
generated with `--output-reproducible` (no timestamp, no random serial), so it too is
byte-stable. `release.json` records the reproducibility metadata
(`deterministic: true`, `build_command`) for each edition.

## What is deliberately not deterministic

Stated plainly, because honest boundaries are part of the trust model:

- **PGP signatures (`.sig`).** OpenPGP detached signatures carry random salt, so the
  signature bytes differ on every run. Only the data they sign is deterministic — the
  manifest and archive bytes reproduce; their signatures do not.
- **Licensed typefaces.** The Klim Type Foundry fonts are not redistributable and are
  excluded from the repository and the archives. A rebuilder without that licence
  reproduces every byte except the fonts; pages render with the CSS fallback stack.

## Scope of the claim

The evidence today is **same-environment / clean-CI-runner reproduction** (the
`build-check` and release runners reproduce the committed bytes from source).
Fully independent off-machine bit-for-bit reproduction across arbitrary toolchains is
a stated goal, not yet a claim — the deterministic archive construction above is the
groundwork for it.
